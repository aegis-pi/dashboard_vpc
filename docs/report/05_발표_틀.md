## 12. Data Pipeline — 데이터 수집 및 전달 (Edge)

- **센서 데이터 경로**
  1. AI & Sensor Pod로 수집된 데이터를 `outbox/tmp/`에 저장합니다.
  2. IoT Publisher 로직을 실행합니다.
  3. 정상 전송 시 MQTT 통신으로 AWS 전송 단계로 진행합니다.
- **스냅샷 이미지 경로**
  4. AI 탐지 결과 화재·넘어짐·굽힘 이벤트 발생 시, 해당 시점의 snapshot을 `outbox/tmp/`에 저장합니다.
  5. Snapshot Publisher 로직을 실행합니다.
  6. 정상 전송 시 Presigned URL을 이용해 AWS 전송 단계로 진행합니다.
- **(a) 실패 처리**: 정상 전송 실패 시 `[a]` 경로로 `quarantine/`으로 이동하며 재전송을 시도합니다.

## 13. Data Pipeline — AWS 전달

- **센서 데이터**
  1. 정상 전송된 데이터를 MQTT를 통해 전달합니다.
  2. MQTT를 통해 IoT Core로 데이터를 전송합니다.
  3. 수신된 데이터를 Lambda를 통해 risk score를 계산합니다.
  4. 실시간 전송된 최신 데이터를 DynamoDB에 `#LATEST`로 저장합니다.
  5. 실시간 전송된 최신 데이터를 S3 `raw/factory-{}` 경로로 저장합니다.
- **스냅샷 이미지**
  6. 정상 전송된 스냅샷 이미지를 Presigned URL을 통해 전달합니다.
  7. 수신된 스냅샷을 S3 `image_snapshot/factory-{}` 경로로 저장합니다.

## 17. 대시보드 Flow

> 구성요소: User · Dashboard(웹 화면) · Route 53 · Cognito · CloudFront · S3 · ECS Fargate · DynamoDB · Lambda Notifier · ElastiCache(Redis)
> 번호는 다이어그램 아이콘과 1:1 — ①~⑤ 첫 화면 로딩·로그인, ⑥~⑧ 실시간 변경 전달, ⑨ 대시보드↔백엔드 실시간 연결.
> 아이콘 매핑(발표자용): ②Route 53 · ③Cognito · ④CloudFront · ⑤S3 / ⑥DynamoDB→Lambda Notifier · ⑦→ElastiCache · ⑧→ECS Fargate · ⑨Dashboard↔ECS Fargate.
> 참고: 로그인(Cognito)은 실제론 화면 로딩(CloudFront·S3) 뒤에 일어나지만, 다이어그램은 구성요소를 좌→우로 배치해 ③에 둠 — 발표엔 무방.

1. (①) 사용자가 대시보드에 접속합니다.
2. (②) 접속 주소를 실제 서버 위치로 바꿔 연결합니다. (DNS)
3. (③) 로그인 인증으로 본인을 확인합니다.
4. (④) CDN·방화벽을 거쳐 안전하게 전달합니다.
5. (⑤) 대시보드 화면(웹앱)을 받아와 사용자에게 보여줍니다. (← 여기까지 첫 화면 로딩)
6. (⑥) 〔실시간〕 데이터가 바뀌면 알림 처리기가 변경을 감지합니다.
7. (⑦) 바뀐 내용을 빠른 메모리 저장소에 전달합니다.
8. (⑧) 백엔드가 그 저장소에서 변경을 받아옵니다.
9. (⑨) 백엔드가 대시보드와 실시간으로 연결돼, 바뀐 상태를 새로고침 없이 갱신합니다.

## 18. 대시보드 — DynamoDB에서 불러오는 데이터 (공장/인프라 상태 확인)

> 구성요소: User ↔ ECS Fargate(백엔드, FastAPI) ↔ DynamoDB. 요청(①~③)과 응답(④~⑥)이 오가는 왕복 구조.

1. (①) 사용자(User)가 대시보드에서 공장·인프라 상태를 요청합니다.
2. (②) 요청이 백엔드 서버(ECS Fargate, FastAPI)에 도착합니다.
3. (③) 백엔드가 데이터베이스(DynamoDB)에서 가장 최신 상태(`#LATEST`)를 조회합니다.
4. (④) DynamoDB가 조회된 상태 데이터를 돌려줍니다.
5. (⑤) 백엔드가 받은 데이터를 화면에 맞게 가공합니다.
6. (⑥) 대시보드가 공장·인프라 상태를 화면에 표시합니다.

- 관련 이미지: `발표 이미지 관련/전체개요.png`

## 19. 사용자 관리 플로우

> 구성요소: Admin · Dashboard · ECS Fargate · **Cognito** · RDS PostgreSQL
> ✅ Cognito 아이콘 추가 완료 (ECS Fargate 아래 분기). 사용자 관리는 Cognito 사용자 풀 생성/삭제를 반드시 동반(`routers/admin_users.py` + `services/cognito_admin.py`). 하단에 **④ 번호 박스 추가 권장**(기존 ①②③ 유지).

1. (①) 관리자(Admin)가 대시보드에서 사용자 계정을 생성·수정·삭제 요청합니다. (관리 권한은 super_admin / org_admin만)
2. (②) 대시보드가 이 요청을 백엔드 서버(ECS Fargate)로 전달합니다.
3. (③) 백엔드가 사용자 정보와 **공장별 접근 권한(RBAC)**을 데이터베이스(RDS PostgreSQL)에 저장하고, "누가·언제·무엇을 했는지"를 감사 기록(AuditLog)으로 남깁니다.
4. (④) 같은 계정을 로그인 인증 서비스(Cognito)에도 반영합니다. Cognito가 실제 로그인을 담당하므로, 계정을 만들면 로그인이 열리고 지우면 로그인이 막힙니다. ← 신규

## 20. 사용자 접근 Flow

> 구성요소: User · Cognito · Dashboard · RDS PostgreSQL
> 참고: RDS 역할(RBAC) 조회는 실제로는 ECS 백엔드(`auth_me`/`principal_from_claims`)가 수행. 다만 본 슬라이드는 **인증 흐름 위주 상위 레벨**이라 ECS는 도면에서 생략하고, 발표 시 "역할 조회는 백엔드(ECS)가 수행"으로 구두 보강. (ECS 아이콘 추가 검토했으나 도면 복잡도·기존 화살표 정리 부담으로 **미적용 결정**)

1. (①) 사용자가 대시보드에 접속해 로그인합니다.
2. (②) 대시보드가 로그인 인증 서비스로 본인 인증(OIDC)을 진행합니다.
3. (③) 인증된 사용자의 역할·권한(RBAC)을 데이터베이스에서 조회합니다.
4. (④) 조회한 권한(접근 가능한 공장·메뉴)을 대시보드가 확인합니다.
5. (⑤) 권한에 맞는 화면과 기능만 사용자에게 보여줍니다. (예: 담당 공장만 조회, 시스템 메뉴는 관리자만)

## 29. AI 챗 플로우 (7단계)

> 구성요소: User · Dashboard · ECS Fargate · Bedrock(Nova Micro) · Bedrock(Nova Pro) · DynamoDB · S3
> Nova Micro = 질문 해석(가볍고 빠름), Nova Pro = 근거 기반 답변 생성(똑똑함).
> 아래 **[슬라이드용]** 1~7을 그대로 박스에 넣으면 다이어그램 화살표와 1:1로 맞습니다. (현재 PPT 박스엔 옛 "일간 레포트 접근" 문구가 남아 있어 교체 필요)

### [슬라이드용] 7개 박스 — 쉬운 말 · 화살표와 1:1

1. (①) User→Dashboard : 사용자가 챗봇에 궁금한 점을 질문합니다.
2. (②) Dashboard→Nova Micro : 가벼운 AI가 질문을 읽고 "무엇을, 어느 기간을 묻는지" 정리합니다.
3. (③) Nova Micro→ECS Fargate : 정리된 질문이 서버로 전달됩니다.
4. (④) **ECS Fargate ↔ DynamoDB·S3 : 서버가 질문에 맞는 실제 데이터를 직접 찾아옵니다 — ★핵심**
   - 그 사용자가 **볼 수 있는 공장·범위의 데이터만** 가져옵니다(권한 확인). 권한 없는 데이터는 답에 절대 안 들어갑니다.
   - 가져오는 것: 실시간 상태·과거 기록(DynamoDB), 일간 보고서·현장 사진(S3)
   - 그래서 답이 "AI가 지어낸 말"이 아니라 **"실제 데이터"를 바탕으로** 만들어집니다.
   - (그림의 점선 ↕ = 질문을 보내고 데이터를 받아오는 양방향)
5. (⑤) ECS Fargate ↔ Nova Pro : 찾아온 데이터를 똑똑한 AI에게 주고, 사람이 읽기 쉬운 답변을 만들게 합니다.
6. (⑥) ECS Fargate→Dashboard : 만들어진 답변이 화면으로 전달됩니다.
7. (⑦) Dashboard→User : 사용자가 챗 화면에서 답변을 확인합니다.

### [발표 보충 / Q&A 노트] 기술 정확 버전 — 슬라이드엔 넣지 말 것

- **실제 구현**: `POST /chat/query`는 ECS Fargate 백엔드가 처리. Bedrock 호출·DynamoDB/S3 조회 모두 백엔드가 수행. (슬라이드는 Dashboard→Nova Micro로 단순화해 그렸지만, 실제로는 ECS가 Nova Micro를 호출함)
- **정확한 내부 순서**: ① Cognito 토큰 검증 → ② Nova Micro로 질문 의도·공장·시간 범위 해석(resolve) → ③ 접근 권한(RBAC) 확인 → ④ DynamoDB·S3에서 근거(Evidence) 조회 → ⑤ Nova Pro가 근거 기반 답변 생성. (RBAC는 화살표 없는 내부 점검이라 다이어그램에선 ④ 안에 포함)
- **강조 멘트**: "AI가 데이터를 직접 뒤지는 게 아니라, 백엔드가 권한 확인 후 실제 데이터를 조회하고 AI는 그 근거를 설명합니다."
- **데이터 출처**: DynamoDB = 최신 상태·이력·그래프(GRAPH#5M), S3 = 일간 보고서·processed 데이터·이미지 스냅샷.
- **폴백(안정성)**: Nova Micro 해석 실패 → 규칙 파서, Nova Pro 답변 실패 → 템플릿 답변으로 대체(ADR 0034). "AI 장애 시에도 서비스가 끊기지 않음."
- **모델 기본값**: resolve=Nova Micro, fast/precise=Nova Pro.

## 31. 화재 시나리오 소개

> 상세: `docs/demo/04_fire_scenario.md`

- **상황**: factory-a 현장에서 온도가 오르고(임계치 **32°C** 초과) 카메라에 화재가 잡히면, 안전점수가 위험 구간까지 떨어지고 공장 상태가 `위험`으로 바뀌며 관제 담당자 **Slack**으로 알림이 갑니다.
- **3단계로 한 사건을 끝까지 추적**합니다:
  1. **실시간 인지** — Environment History에서 온도·화재 점수가 같이 오르고 안전점수가 위험으로 떨어지는 걸 실시간 확인
  2. **증빙 확인** — 화재 점수가 튄 시각의 이미지 스냅샷을 찾아 사진으로 확인
  3. **AI 요약** — AI 채팅에 자연어로 물어 위험 상황과 증빙 사진을 요약받기
- 한 사건을 **수집 → 탐지 → 알림 → 증빙 → 설명**까지 끊김 없이 보여줍니다.

> 영상은 파트별 슬라이드(32·33·34)로 분리. 각 슬라이드엔 소제목+한 줄만, 대사는 발표자가 영상 위에 구두로(출처: `docs/demo/04_fire_scenario.md`).

## 35. 클라우드 에러 시나리오 소개

## 37. 사용자 관리 시나리오 설명

> 상세: `docs/demo/03_user_account_scenario.md`

- **핵심**: 로그인은 **Cognito**(인증·임시 비밀번호·세션), 권한은 **RDS**(접근 가능한 공장 등 메타데이터)가 담당. 백엔드가 둘을 매칭해 **권한에 맞는 공장만** 보여줍니다.
- **3단계로 시연**:
  1. **생성 + 첫 로그인** — 관리자가 공장 관리자 계정 생성 → 초대 메일·임시 비밀번호 → 첫 로그인 시 비밀번호 변경 → `factory-a`만 보임
  2. **권한 수정** — 권한을 `factory-a` → `factory-a + factory-b`로 변경 → 신규 사용자 화면의 공장 범위가 **즉시** 바뀜
  3. **삭제** — 계정 삭제 시 **Cognito 계정 + RDS 권한을 함께 제거** → 다시 로그인 불가

## 38. 사용자 관리 시나리오 영상

**① 생성 + 첫 로그인**
- 관리자가 사용자 관리에서 공장 관리자(`factory-a`) 생성 → 목록에 추가
- 초대 메일·임시 비밀번호 수신 → 신규 사용자가 첫 로그인 시 비밀번호 변경
- 신규 사용자 화면에 `factory-a`만 노출 / Cognito Users에 계정 생성 확인

**② 권한 수정**
- 권한 `factory-a` → `factory-a + factory-b` 변경·저장
- 신규 사용자 화면 새로고침 → 보이는 공장 범위가 즉시 변경 (사이드바·Fleet·선택기)

**③ 삭제**
- 계정 삭제 → 목록에서 사라짐
- 신규 사용자 재로그인 시도 → 로그인 불가 / Cognito User Pool에서도 사라짐
